# Оплата ключа на сайте: что сделано на фронтенде и что должен дать сервер

Часть 2 задания `docs/tasks/2026-11-20-api-payments-modules.md`. Фронтенд готов, серверных маршрутов пока нет.

## Что есть на сайте (`api.html`, `assets/js/buy.js`)

Мастер из четырёх шагов, после оплаты пятый экран с ключом:

1. **Тариф**: Plan switch (пружины из `tokens.css` референса designbookmark.com). Цены в долларах: **Basic $3, Pro $7, Ultra $12** за 30 дней, рядом в звёздах для Telegram (100 / 400 / 1 500 ⭐). Лимиты берутся из таблицы `PLANS` в начале `buy.js` (держать в одном ряду с таблицей тарифов в `api-docs.html` и таблицей `tiers` в D1).
2. **Проект**: название, тип (сайт, приложение, сервер, другое), описание, домены (только для сайта, проверяются как имена хостов), e-mail.
3. **Условия и подпись**: показывается текст `#terms` из `api-docs.html` (подгружается тем же сайтом), галочка «прочитал», полное имя и подпись пальцем или мышью (Signature pad: Kokonut UI, MIT, переписан на чистом JS). Версия условий = первые 12 символов SHA-256 от английского текста раздела `#terms`.
4. **Оплата**: карта/PayPal (Paddle), USDT, Telegram Stars.
   - **Stars работает сейчас**: открывает бота `https://t.me/VetroBook_API_bot?start=plan_<basic|pro|ultra>` (бот должен понимать этот параметр). Подпись при этом **нигде не сохраняется**: человеку предлагается скачать свою копию (`vetro-api-agreement-<дата>.html`).
   - **Карта и USDT отключены** (метка «скоро»), пока в `buy.js` стоит `BILLING.on = false`.
5. **Результат** (`api.html?order=<id>`): опрос статуса заказа, ключ показывается один раз.

Всё, что вводит человек или возвращает сервер, выводится через `textContent`.

## Что должен сделать сервер (Worker в репозитории приложения)

Правила из задания: заказы и ключи только на сервере; базы не делить; секреты (`PADDLE_*`, ключи шлюза) только через `wrangler secret put`; ключ выдаётся **только по вебхуку**, не по возврату браузера; подпись вебхука проверяется, события идемпотентны по id события.

### `POST /v1/billing/checkout` (без ключа API, CORS открыт для сайта)

Тело запроса (JSON):

```json
{
  "plan": "basic | pro | ultra",
  "method": "card | usdt",
  "lang": "en | ru",
  "email": "me@example.com",
  "project": { "name": "My Site", "type": "site | app | server | other", "description": "…", "domains": ["example.com", "www.example.com"] },
  "contract": {
    "signer": "Ivan Petrov",
    "signedAt": "2026-11-21T17:32:22.000Z",
    "termsVersion": "f3bee9bb6eb9",
    "signatureSvg": "<svg xmlns=…>…</svg>"
  }
}
```

Ответ `200`: `{ "orderId": "…", "url": "https://…" }`, где `url` — страница оплаты (Paddle checkout или инвойс шлюза), на которую сайт перенаправляет браузер. Адрес возврата после оплаты: `https://vetrostudio.bid/api.html?order=<orderId>`. Только `https://`. Ошибки: `400` (неверные поля), `429`.

Что сервер сохраняет вместе с заказом: всё из тела запроса (подпись как SVG), дату и время, версию условий, язык. Проверять: `plan` из списка, `domains` как имена хостов, длину полей, размер SVG.

### `POST /v1/billing/webhook/paddle`, `POST /v1/billing/webhook/crypto`

Проверка подписи, идемпотентность, запись в `orders` рядом с заказами бота, выдача ключа существующим кодом (`scripts/new-key.mjs` / `access.js`), письмо с ключом на e-mail.

### `GET /v1/billing/order/{id}`

Ответ: `{ "status": "pending | paid | failed", "key": "vk_…" }`. Поле `key` есть **один раз**, при первом запросе после `paid`; дальше только `status`. Страница опрашивает раз в 3 секунды до 2 минут.

## Как включить

Когда маршруты работают: в `assets/js/buy.js` поставить `BILLING.on = true`, проверить в браузере на `vetrostudio.bid` (запросы должны быть `200` с `access-control-allow-origin`), поднять версию `?v=` у скриптов в `api.html`.
