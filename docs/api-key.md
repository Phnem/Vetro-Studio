# Ключ сайта для API каталога книг

Для сайта выдан отдельный ключ тарифа **Ultra**, **бессрочный** (срока действия нет), привязанный к доменам сайта. Он нужен, чтобы после
включения обязательных ключей (`ACCESS_MODE = "enforce"` на `api.vetrostudio.bid`) страница `api.html` и всё остальное, что ходит в API, продолжило работать.
Сейчас ключи ещё необязательны: запросы без ключа проходят, а с ключом проверяются. **До включения обязательности сайт должен начать слать ключ.**

## Ключ

```
vk_ultra_rq4dkgxrfnoo2vaple3t2w6wk546z5tp
```

| | |
|---|---|
| Идентификатор (виден в панели) | `k_6fa9d9bd09bb` |
| Тариф | Ultra: 20 запросов в секунду, 600 в минуту, 200 000 в сутки (UTC), `limit` до 50, `ids` до 40, обложки и индекс доступны |
| Домены | `vetrostudio.bid`, `www.vetrostudio.bid`, `phnem.github.io` |
| Срок | бессрочно (отзывается вручную) |

Ключ лежит в публичном репозитории и в коде страницы, то есть виден любому. Это нормально для ключа сайта, но поэтому он защищён не секретностью, а
ограничениями: проверка домена (запрос из браузера с чужого сайта получит `403 origin_not_allowed`), суточная квота и возможность заменить ключ.
Проверка домена не останавливает скрипт с сервера, который подделывает заголовок `Origin`: от этого защищает только квота и замена ключа.

## Как пользоваться

Заголовок в каждом запросе к `api.vetrostudio.bid`:

```js
const BOOKS_API = "https://api.vetrostudio.bid";
const BOOKS_KEY = "vk_ultra_rq4dkgxrfnoo2vaple3t2w6wk546z5tp";
const res = await fetch(`${BOOKS_API}/v1/search?q=${encodeURIComponent(q)}&limit=20`, { headers: { Authorization: `Bearer ${BOOKS_KEY}` } });
```

- Заголовок `Authorization` в браузере вызывает preflight (`OPTIONS`); API на него отвечает `204` и разрешает `authorization` и `x-api-key`, отдельная настройка не нужна.
- Обложки в `<img src>` заголовок задать не позволяют: добавляйте `&key=<ключ>` к адресу: `…/covers/small/<id9>.avif?v=<cv>&key=<ключ>`.
  Ключ из адреса сервер не передаёт дальше и не кэширует вместе с картинкой.
- Ключ отправлять **только** на `api.vetrostudio.bid`. Запасной адрес (`vetro-books-api.….workers.dev`) принимает тот же ключ, но не отправляйте его на другие домены.
- Ответы несут `X-RateLimit-Remaining-Minute` и `X-RateLimit-Remaining-Day`; на `429` подождите `Retry-After` секунд и не долбите повторно.
- Ключ держать **одной константой** рядом с `BOOKS_API`, чтобы заменить его одним изменением.

## Что сделать на сайте до включения обязательных ключей

1. Добавить заголовок `Authorization` во все запросы к API в `assets/js/api.js` и `?key=` к адресам обложек.
2. Убрать из `api.html` и переводов (`assets/js/i18n.js`) утверждения «No keys / без ключей / keys needed: 0 / no sign-up»: с ключами они перестанут быть правдой для остальных клиентов.
   Для посетителей сайта ничего не меняется, но страницу для разработчиков надо переписать: как получить ключ, тарифы, условия. Текст возьмите из
   `docs/api/README.ru.md` и `docs/api/terms.ru.md` репозитория приложения (там же английские версии), а не придумывайте заново.
3. Проверить в консоли браузера: запрос с `https://vetrostudio.bid` даёт `200`, а `curl` с `Origin: https://example.com` и этим ключом даёт `403 origin_not_allowed`.

## Если ключ утёк или нужен другой

Не меняйте ключ сами и не создавайте новые: ключи выдаёт и отзывает владелец (панель `https://dash.vetrostudio.bid`, вход через Cloudflare Access).
Новый ключ сайту выдаёт владелец; после замены старый перестаёт работать сразу (в пределах минуты), поэтому замените константу в коде в тот же момент.
Если API отвечает `401 invalid_key` или `403 key_revoked`, значит ключ заменён или отозван: сообщите владельцу.
