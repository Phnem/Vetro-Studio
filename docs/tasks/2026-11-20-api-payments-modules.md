# Задание для сайта: API шире книг, оплата ключа на сайте, живая страница модулей

Дата постановки: 20 ноября 2026. Автор постановки — владелец Vetro; задание собрано из трёх его пунктов в один документ.
Сайт — чистые HTML/CSS/JS без сборки (см. `README.md` и `CLAUDE.md`). Любой новый видимый текст получает английский
вариант в HTML и русский в `assets/js/i18n.js`.

> **Как читать референсы.** Ниже приведены промпты владельца для анимированных компонентов (designbookmark.com,
> Kokonut UI). Они написаны для любых сайтов: дизайн в них — образец движения, а не готовый вид. Компонент обязательно
> переносится в дизайн-код этого сайта: постерная палитра (`--red #e1251b`, `--cream #fff1d6`, `--ink #150d0b`,
> `--orange #ff5a1f` и остальные токены из `assets/css/site.css`), шрифты (`--font-display` Unbounded, `--font-body`
> Manrope, `--font-mono` JetBrains Mono), радиусы и тени сайта. Пружины берутся **ровно** из `tokens.css` референса
> (жёсткость и затухание), чтобы движение было тем же. Демо-тексты заменяются настоящими текстами Vetro.
> Если место на странице не названо прямо — **спросить владельца**, прежде чем ставить компонент на страницу.

Порядок работы: часть 1 → часть 3 → часть 2. Часть 2 (оплата) требует серверной стороны в репозитории приложения
и ответов владельца на открытые вопросы (в конце документа), поэтому её стоит начинать последней.

## Часть 1. API теперь не только книжный: что поменять на сайте

### Что изменилось (проверено 20.11.2026 по живому API и боевой D1)

API по-прежнему один: `https://api.vetrostudio.bid` (запасной адрес `https://vetro-books-api.1234idelchik.workers.dev`),
те же ключи, те же тарифы и ошибки. Но каталог теперь состоит из **трёх баз**:

| База | `kind` | Записей в облаке | С обложкой | Формат id |
|---|---|---:|---:|---|
| Книги и аудиокниги | `book` | 294 033 | 227 077 | девять цифр, `000000771` |
| Аниме | `anime` | 37 399 | 35 035 | `A` + 8 цифр, `A00000050` |
| Фильмы | `movie` | 45 571 | 45 371 | `M` + 8 цифр |
| Сериалы | `tv` (в строке `t: "tv_series"`) | 129 056 | 120 048 | `S` + 8 цифр |

Итого около **294 тыс. книг и 212 тыс. тайтлов** (аниме, фильмы, сериалы). Файловый индекс для приложений (`/v1/manifest`,
Ultra) — версия 6, в базе 228 756 книг. Цифры растут после каждой выгрузки: на сайте писать округлённо («около 294 000»,
«более 200 000») и не обещать точных значений.

Маршруты (источник правды — `tools/books-api/src/worker.js` и публичная документация `docs/api/README.md` +
`README.ru.md` в репозитории приложения `D:\AndroidStudioProjects\Vetro-collection`):

| Маршрут | Что делает | Есть на сайте сейчас |
|---|---|---|
| `GET /v1/find?q&kind=all\|anime\|movie\|tv\|book&limit` | **Единый поиск по всем трём базам.** У каждой записи есть `kind`; при `kind=all` списки баз ранжируются отдельно и перемежаются (лучшее из каждой базы — наверху), `counts` показывает, сколько пришло из каждой. Неизвестный `kind` → `400 bad_kind` | нет |
| `GET /v1/media/search?q&type=anime\|movie\|tv&limit` | поиск только по медиа | нет |
| `GET /v1/media/{id}` | один тайтл с карточкой (`detail`: описание, жанры, эпизоды, длительность, статус, рейтинги, `ext`) | нет |
| `GET /v1/media?ids=A…,S…` | пакет строк по id | нет |
| `GET /v1/media/ext?ids=anilist:…,mal:…,shikimori:…,tmdb:…,imdb:…&kind=` | **новое:** найти тайтлы Vetro по id других сервисов (до 40 id), в ответе поле `via` — по какому id нашлось | нет, и в публичной документации тоже нет |
| `GET /covers/media/{small\|large}/{id}.avif?v={cv}` | обложки медиа (правила как у книжных) | нет |
| `GET /v1/search`, `/v1/books/{id}`, `/v1/books?ids=` | книжные маршруты, работают как раньше и теперь тоже несут `kind` | да |
| `GET /covers/{small\|large}/{id}.avif`, `/v1/manifest`, `/v1/index/…` | как раньше | да |

Важная оговорка для документации: некоторые тайтлы есть и как `anime`, и как `tv_series`, потому что пришли из разных
баз; клиент может показывать оба или схлопывать по `ext`.

### Что сделать на сайте

1. **Название и подача.** Сейчас продукт везде называется «VetroBook API» и описан как каталог книг
   (`api.html`, `api-docs.html`, карточка API на `index.html`, `og:description`). Переименовать в **Vetro API** (или
   «Vetro Catalog API» — уточнить у владельца) и подавать как единый каталог книг, аниме, фильмов и сериалов.
   Заменить устаревшие цифры «269,000 books» во всех местах (`api.html` meta/og, `index.html` `index.api.text`, i18n).
2. **`api.html` — живой поиск.** Сейчас он ходит в `/v1/search` (книги). Перевести на `/v1/find`: переключатель
   направлений «Всё / Аниме / Фильмы / Сериалы / Книги» (`kind`), бейдж типа на каждой карточке по полю `kind`,
   обложки медиа по `/covers/media/…`, карточка тайтла по `/v1/media/{id}`. Всё из ответа API выводится через
   `textContent`, не `innerHTML` (правило уже записано в `assets/js/api.js`). Ключ сайта и заголовок `Authorization` —
   как описано в `docs/api-key.md`.
3. **`api-docs.html`.** Добавить разделы: обзор трёх баз (таблица выше), `/v1/find` с примером ответа,
   `/v1/media/*`, `/v1/media/ext`, обложки медиа, поля строки медиа (`t`, `ru`, `en`, `ro`, `orig`, `y`, `st`, `f`, `cv`)
   и карточки (`detail`). Тексты брать из `docs/api/README.md` / `README.ru.md` приложения, а `/v1/media/ext` описать
   по коду `tools/books-api/src/media.js` (и попросить владельца добавить его и в README приложения).
4. **`docs/books-api.md`** в этом репозитории описывает только книги — дополнить разделом про медиа и `/v1/find`
   (или переименовать в `docs/catalog-api.md` и поправить ссылки в `CLAUDE.md`).
5. Проверка: `curl -s "https://api.vetrostudio.bid/v1/find?q=death%20note&kind=all"` → 200, в ответе есть `kind`;
   на странице во вкладке Network все запросы 200 с `access-control-allow-origin: *`.

## Часть 2. Оплата ключа API прямо на сайте

### Сейчас

Ключи продаются только через Telegram-бота за Telegram Stars (Basic 100 ⭐, Pro 400 ⭐, Ultra 1 500 ⭐ за 30 дней; лимиты —
таблица `tiers` в D1, ADR `docs/adr/0003-api-access-keys-and-tiers.md` в репозитории приложения). Бот пишет в таблицы
`customers`/`orders` (схема `tools/books-api/schema/bot.sql`), панель `dash.vetrostudio.bid` их читает. С апреля 2026
покупатели из России покупают звёзды только через посредников, а сайт оплату не принимает вовсе.

### Решение владельца по платёжным системам (20.11.2026)

| Роль | Сервис | Почему | Что проверить до подключения |
|---|---|---|---|
| **Основной** (весь мир, карты, PayPal, Apple/Google Pay) | **Paddle** — merchant of record: продавцом выступает Paddle, он считает и платит НДС/налоги, принимает карты и кошельки, ведёт подписки | один договор вместо налогов в десятках стран; оверлей-чекаут подключается скриптом `Paddle.js` на статической странице; вебхуки на Worker | **Покупателей из России и Беларуси Paddle не обслуживает**: оплата блокируется на чекауте, подписки из РФ отменены ещё в 2023 ([Paddle: sanctions](https://paddle.com/help/legal/sanctions/impact-of-sanctions-on-russia-and-belarus)). Проверить: что страна владельца есть в [списке поддерживаемых продавцов](https://www.paddle.com/help/start/intro-to-paddle/which-countries-are-supported-by-paddle); что Paddle пропустит товар «доступ к API каталога» при проверке сайта (у части данных — описаний и обложек — не решён вопрос лицензий на продажу, см. «Открытые вопросы»). Комиссия по сторонним обзорам около 5% + $0,50 — сверить на paddle.com/pricing |
| **Для покупателей из России** | кандидат — **lava.top** (Lavalane LTD, Кипр): продукты, инвойсы и подписки по Public API (OpenAPI 3, SDK на TypeScript/Kotlin), комиссия по обзорам ~8%, вывод от 20 €/$ | Paddle Россию не принимает, нужен отдельный путь для российских карт | **Не подтверждено**, что lava.top принимает карты российских банков и выплачивает владельцу за рубеж: спросить поддержку до разработки. Запасной кандидат — Tribute (Telegram, TRBT Limited, Кипр, ~10%), те же вопросы. Если ни один не подходит — российским покупателям остаются USDT и Stars |
| **Второй/третий способ** | **USDT** через крипто-шлюз: **NOWPayments** или **Cryptomus** | работает для покупателей из любой страны, включая Россию; комиссия 0,4–1%; инвойсы, вебхуки, у обоих заявлено автопродление | налоги и возвраты остаются на владельце (шлюз не merchant of record); выбрать шлюз по актуальным тарифам и подписи вебхуков; принимать только USDT (TRC-20 и/или TON — решить), сумма = цена тарифа в $ |
| **Остаётся** | Telegram Stars через бота | уже работает | на сайте — кнопка «Оплатить в Telegram», ведущая в бота с выбранным тарифом (deep link `?start=plan_pro`) |

Цены на сайте — в долларах (Paddle и USDT) и в звёздах (бот). Долларовые цены тарифов **решает владелец** (открытый вопрос).

### Поток покупки на сайте

1. **Выбор тарифа** — компонент Plan switch (ниже). Basic / Pro / Ultra с лимитами из таблицы тарифов.
2. **О проекте** — название, короткое описание, тип (сайт, мобильное приложение, сервер, другое), домены для браузерного
   ключа (ключ сайта работает только с указанных доменов), e-mail для чека и восстановления.
3. **Подписание договора** — виртуальное подписание условий использования. Условия уже есть: раздел `#terms` на
   `api-docs.html` (источник текста — `docs/api/terms.md` / `terms.ru.md` приложения; **это черновик, юрист не смотрел**).
   Шаг показывает условия (или их краткую выжимку со ссылкой на полный текст), галочку «Я прочитал условия» и поле
   подписи — компонент Signature pad (ниже). Кнопка «Дальше» активна только при отмеченной галочке и непустой подписи.
   Вместе с заказом сохраняется: подпись (SVG-путь или PNG), имя, дата и время, **версия условий** (хэш текста) и язык.
   Раздел 8 условий («какие данные хранит сервис») при этом нужно дополнить: сейчас там перечислены только данные из
   Telegram, а подпись, e-mail и домены — новые данные.
4. **Оплата** — выбор способа: карта/PayPal (Paddle, оверлей), USDT (инвойс шлюза), из России (сервис из таблицы,
   если подтвердится), Telegram Stars (переход в бота).
5. **Ключ** — после подтверждённой оплаты (только по вебхуку, не по возврату браузера) ключ показывается **один раз**
   на странице успеха и уходит письмом. Продление — по подписке Paddle / новым инвойсом за 30 дней.

### Серверная часть (в репозитории приложения, не на сайте)

Сайт статический, поэтому создание заказов, вебхуки и выдача ключей живут в Worker:
`tools/books-api` (или отдельный воркер `vetro-billing` с той же D1 `vetro-books` — базы не делить, правило владельца).
Минимум: `POST /v1/billing/checkout` (создать заказ и вернуть параметры чекаута/инвойса), `POST /v1/billing/webhook/paddle`,
`POST /v1/billing/webhook/crypto`, `GET /v1/billing/order/{id}` (статус для страницы успеха), проверка подписи каждого
вебхука, идемпотентность по id события, запись в `orders` рядом с заказами бота, выдача ключа существующим кодом
`scripts/new-key.mjs`/`access.js`. Секреты (`PADDLE_*`, ключи шлюза) — только `wrangler secret put`, никогда в сайт или
репозиторий. Это отдельная задача для сессии в репозитории приложения; сайт пишет только фронтенд под эти маршруты.

## Часть 3. Страница модулей: живые демо вместо видео

### Сейчас

`modules.html` показывает три модуля из приложения Vetro: **frosted glass** (матовое стекло для Compose), **motion**
(одна таблица пружин) и **chunked download** (докачиваемый загрузчик). У первых двух — видео
(`assets/video/modules/frostedglass.mp4`, `animation.mp4`), у загрузчика — видео замеров и таблица бенчмарка. Скачать
можно только zip-архивы с GitHub Releases (`Phnem/Vetro-Modules`, внутри `SKILL.md` + `GUIDE.txt`).

### Что нужно

1. **Убрать видео у стекла и анимации** и рисовать демо вживую кодом (DOM + CSS/JS) прямо на странице: стекло — живые
   слои матового материала поверх движущегося фона с тёмной и светлой темой; анимация — те же паттерны, что на видео,
   на пружинах **из таблицы токенов самого модуля** (значения брать из `SKILL.md`/`GUIDE.txt` модуля в
   `Phnem/Vetro-Modules`, не придумывать), с подписью активного токена, как сейчас подпись над видео
   (`mod.m.inside`). Референс подачи — сетка живых карточек https://designbookmark.com/motion: компонент работает сам,
   на него можно нажать/потянуть, есть переключатель темы и замедления.
2. **Загрузчик не трогать по сути**: там нечего показывать вживую, остаются замеры (таблица бенчмарка, как сейчас);
   видео бенчмарка можно оставить или заменить анимированным графиком — на усмотрение, без потери цифр.
3. **Возле каждой карточки две кнопки**: «Скачать скилл» (`SKILL.md`) и «Скачать инструкцию» (`GUIDE.txt`) —
   отдельными файлами, **без архива**. Атрибут `download` работает только для файлов с того же домена, поэтому
   файлы положить в репозиторий сайта (`assets/modules/<module>/SKILL.md`, `GUIDE.txt`) и указать источник/версию
   (тег релиза Vetro-Modules), либо ссылаться на отдельные файлы релиза GitHub, если они там будут. Архивы-кнопки
   в секции `#download` заменить этими парами (или оставить zip третьей, второстепенной ссылкой — спросить владельца).
4. Демо уважают `prefers-reduced-motion` (критическое затухание, как в `motion.js` референса), не крутятся вне экрана
   (IntersectionObserver останавливает цикл), не грузят страницу на телефоне; тексты EN + RU.
5. Проверить на телефоне и десктопе, в обеих темах; затем рассказать владельцу простыми словами, где смотреть.
