01Overview

A read-only HTTP API of the Vetro catalogue: books and audiobooks, anime, movies and series. Search, cards with descriptions and genres, and cover images.

Base URLhttps://api.vetrostudio.bid
FormatJSON, UTF-8; covers are AVIF images
ProtocolHTTPS only, CORS enabled for browsers
CatalogueAbout 294,000 books and audiobooks and over 200,000 anime, movies and series (titles in Russian, English, romaji and the original language), refreshed regularly
AccessAn API key per client, obtained through a Telegram bot, in three plans
AvailabilityBest effort, no uptime guarantee (see the terms of use)

Four databases, one key

The catalogue consists of separate databases that share a key, plan limits and errors. Every result carries kind, so a client always knows where an item came from. Counts are rounded and grow with every data load.

DatabasekindItemsId
Books and audiobooksbook~294,000nine digits, 000000771
Animeanime~37,000A and eight digits, A00000050
Moviesmovie~45,500M and eight digits
Seriestv (t: "tv_series")~129,000S and eight digits

Some titles exist both as anime and as a series because they come from different databases. A client can show both, or merge them by the ids in ext.

02Get a key

  1. Open the Vetro API bot in Telegram, @VetroBook_API_bot, and choose a language.
  2. Tell the bot about your project: its name, a short description, the kind (website, mobile app, server, other), the domains (for websites), whether it is commercial and roughly how many requests a day you expect. The bot recommends a plan.
  3. Read and accept the terms of use, then pay for the plan in Telegram Stars (30 days per payment).
  4. The bot shows your key once. The service stores only a hash of it. If you lose the key, /rotate issues a new one.

04Authentication

Send the key in one header:

HTTP
Authorization: Bearer vk_pro_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
  • X-Api-Key: vk_… is accepted as well.
  • For <img> tags, where headers cannot be set, covers also accept ?key=vk_… in the link.
  • Keys look like vk_<plan>_<32 characters>.
  • Only GET /v1/health works without a key.

A key in a public page is visible to everyone. Never put a key you cannot afford to lose into a web page without the domain restriction. Website keys are tied to your domains by the bot; keep keys for servers and apps out of public repositories.

05Endpoints

All paths are relative to https://api.vetrostudio.bid. Book ids are nine-digit strings, for example 000000771; anime, movie and series ids are a letter and eight digits, for example A00000050.

GET/v1/healthNo key

{"ok":true}

GET/v1/find?q=<text>&kind=<all|anime|movie|tv|book>&limit=<n>

One search over the books, anime, movie and series databases, or over just one of them. Every result carries kind. It counts as a search for the plan’s limits; limit is capped by the plan.

  • kind=all (the default): each database is ranked on its own and the lists are interleaved, so the best match of every database is near the top. counts says how many items came from each.
  • kind=anime, movie, tv or book: only that database is searched. Use it when the user has already chosen a direction, for example a screen with “Anime”, “Series” and “Books” buttons.
  • An unknown kind returns 400 bad_kind with the allowed values.
  • Search matches Latin, Cyrillic and transliterated titles; Japanese characters are not searchable.
JSON · /v1/find?q=death%20note&kind=all&limit=3 (abridged)
{ "q": "death note", "kind": "all",
  "counts": { "anime": 1, "tv": 1, "movie": 1 },
  "items": [
    { "kind": "anime", "id": "A00000051", "t": "anime",
      "ru": "Тетрадь смерти", "en": "Death Note", "ro": "Death Note",

GET/v1/search?q=<text>&limit=<n>

Full-text search over titles and authors in both languages. limit defaults to 20 and is capped by the plan.

  • The query is normalised on the server (case, diacritics, ё→е, transliteration), so “chayka”, “Чайка” and “чайка” find the same books.
  • Words are matched as prefixes and combined with AND. If almost nothing is found, the search relaxes to OR.
  • Fewer than 2 characters return an empty list. The server does not correct typos.
JSON · /v1/search?q=dune&limit=1
{ "q": "dune", "items": [
  { "id": "000001192", "ru": "Дюна", "en": "Dune series",
    "ra": "Кевин Джей Андерсон", "ea": "Kevin J. Anderson",
    "y": 1965, "f": 5, "cv": 6013617 }
] }

GET/v1/media/ext?ids=anilist:16498,tmdb:13916&kind=<anime|movie|tv>

Finds Vetro titles by their ids in other services. Up to the plan’s ids maximum ids, each as service:id; the services are anilist, mal, shikimori, tmdb and imdb. Every returned row has via, the id it was found by. It counts as a book lookup.

  • One TMDB number can match a movie and a series, because TMDB numbers them separately. Pass kind when you know it.
  • Ids that do not look like service:id are dropped. An unknown kind returns 400 bad_kind; no valid ids return an empty list.

{ "items": [

    "ru": "Атака титанов", "en": "Attack on Titan", "y": 2013, "f": 3, "cv": 7597630,
    "ext": { "mal": 16498, "shikimori": 16498, "anilist": 16498, "anidb": 9541, "kitsu": 7442 } }
] }
GET/covers/{small|large}/{id}.avif?v={cv}Pro · Ultra

The cover image: small for lists, large for a book page. Needs a plan with covers, and a book that has one (flag f & 1).

  • AVIF is displayed by browsers and by Android 12 and later. Use another source on older systems and keep a placeholder.
  • Responses are immutable: cache them for good, and change v when the book’s cv changes.
HTML
<img src="https://api.vetrostudio.bid/covers/small/000000771.avif?v=7013464&key=vk_pro_…" width="200" height="300" alt="">

Covers of anime, movies and series. The same rules as for book covers: it needs a plan with covers and a title with the flag f & 1, responses are immutable, and v is the title’s cv. The licence of each cover is in detail.cover.lic.

The offline search index used by the Vetro app: a manifest plus versioned base and delta files (zstd-compressed SQLite). Range requests are supported.

07Errors and limits

Successful responses carry X-RateLimit-Limit-Minute, X-RateLimit-Remaining-Minute, X-RateLimit-Limit-Day and X-RateLimit-Remaining-Day. Search and book responses are cacheable at the edge (10 minutes and a day): respect Cache-Control and ETag where they are present.

Errors are JSON: {"error": "<code>"}.

HTTPerrorMeaning
401missing_key, invalid_keyNo key, or an unknown key
403key_revoked, key_expiredThe key was revoked or its 30 days ended: renew it in the bot
403origin_not_allowedA browser request from a domain that is not on the key
403tier_forbids_routeCovers or the index on a plan without them
429rate_limitedA limit was hit: scope is second, minute or day. Wait retry_after seconds (header Retry-After)
400, 404—A malformed request, or an unknown book
  • Retry on 429 and 5xx with an exponential pause. Do not retry other 4xx errors.
  • For search-as-you-type, debounce 250–300 ms and cancel the previous request with AbortController.
  • Do not add extra parameters such as a timestamp: they break the cache.

08Quick start

JavaScript
const API = "https://api.vetrostudio.bid";
const KEY = "vk_pro_...";

const res = await fetch(`${API}/v1/search?q=${encodeURIComponent("Дюна")}&limit=5`, {
  headers: { Authorization: `Bearer ${KEY}` }
});
const { items } = await res.json();

// for an <img src>: headers cannot be set, so the key goes into the link
const cover = `${API}/covers/small/${items[0].id}.avif?v=${items[0].cv}&key=${KEY}`;
curl
curl -H "Authorization: Bearer $KEY" "https://api.vetrostudio.bid/v1/books/000000771"

09Technical notes

  • Runs on Cloudflare Workers at the edge; data is in Cloudflare D1 (SQLite with FTS5) and R2 (covers and index files).
  • Responses come from the Cloudflare edge: cached ones are fast, searches that reach the database take longer. No latency is guaranteed.
  • Request metadata (IP addresses, user agents) is not logged. Per-key counters (requests per route and day) are kept to enforce plans and to show /usage.
  • The catalogue is refreshed without downtime and ids are stable. New fields may appear in responses, so ignore keys you do not know.
  • Changes that would break existing clients would come under a new path prefix (/v2).
